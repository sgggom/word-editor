# 字页关卡台

单文件关卡编辑器，双击 `wordpages-level-desk.html` 在浏览器打开，无需安装。

在线地址（启用 GitHub Pages 后）：https://sgggom.github.io/word-editor/

启用方式：仓库 Settings > Pages，Branch 选 **main**、文件夹选 **/ (root)**。根目录的 `index.html` 与 `wordpages-level-desk.html` 内容相同，打开上述地址即进入编辑器。空文件 `.nojekyll` 用来关闭 Jekyll 处理。

## 目录

- `wordpages-level-desk.html` — 编辑器本体（单文件，本地双击即可用）
- `index.html` — 与上面完全相同的副本，供 GitHub Pages 根地址使用
- `sample_320_levels.json` — 测试时生成并导出的 320 关
- `src/` — 生成器与界面脚本（`gen.js`、`batch_ui.js`）、词库与策略、无头测试和截图
- `verify/` — 独立 Python 校验脚本、负样本和 320 关校验报告
- `shots/` — 多宽度布局截图与布局测试

字页关卡台 v4
=============

v4 修复：关很多（几百上千关）时页面不再无限变宽。关序柱子只在自己那一栏里左右滚动，
整页不会横向滚动，顶部按钮不动。超过 150 关柱子变窄，超过 400 关更窄并隐藏关号；
选中的关会自动滚到可见处；关序栏左上角可以输入关号直接跳转。柱子下面的重复提示只占一行，
放不下用省略号，鼠标悬停看全文。生成器逻辑没有改。

（以下为 v3 说明）

打开 wordpages-level-desk.html（双击或用浏览器打开）。不需要安装，不改游戏仓库。
v2 的功能都在：手动排关、四个难度维度、试玩、导入 Word Tiles / Zen、导出游戏 JSON {g,t,e,n,o}。

新增：顶上「批量生成」
--------------------
设置：起始关号、关数、插在当前关后面或替换整条关序、起点/终点难度、爬升用多少关、
每几关一个峰值、峰后回落幅度、一格最多用几次、允许的棋盘尺寸、随机种子（同样设置 + 同样种子 = 同样的关）。
下面的小曲线是难度预览：缓慢爬升，每段末尾一个峰值，峰后马上回落（Word Tiles 的节奏）。

怎么出一关（先构造）
  1. 按难度定四个维度：必答数、棋盘尺寸、最长词长度、词汇门槛（Zipf 下限；前段只用 easy，难度高时最多 1 个 hard，标为“生僻”）。
  2. 先放一个最长的词，再用 3–4 字母的熟词一条条铺，每条都是真正上下左右相连、不重复用格的路径，直到每一格都有字母。
  3. 再从这块盘上连得出的熟词里补到目标必答数（约八成是 3–4 字母）。
  4. 每格的使用次数 n = 这些路径经过它的次数。所以一开始就有一套完整解，最后一个词也是连好的。
  5. 额外词 = 盘上能连出的其余所有校验词（3–10 字母）。

怎么查（再穷举）
  每一关都把“所有找词顺序 × 每个词所有可走路径”完整走一遍：
  - 从开局必须能走完；
  - 任何一种走法都不能走进死局（某个时候剩下的词怎么都连不出来）。有一个死局这一关就丢掉重出；
  - 游戏自己的 solve()（6 万步预算）也必须在开局算得出解。
  丢掉的草稿按原因计数，生成完显示在面板里。条件太紧时会自动把这一关降一点难度再试，也会写出来。

必答词的规则：只从分级词库 question_words_v2 取；不用专业词、温和词（ass/sex 等那 23 个，只能当额外）、
flagged_offensive 里的词、屏蔽词；前后 10 关内不重复。

生成后
  生成的关会进到上面的关序里，可以照常点开手改。没改过的关，导出时用构造出来的使用次数；
  改了字母或必答，就按当前盘面重算，检查栏会提示。每一关的检查栏都多了一行“穷举试玩”的结果（手排的关也有）。
  超过 40 关浏览器不会自动保存，记得点「保存关序」。

独立校验脚本
------------
verify/verify_levels.py 是另写的 Python 脚本，不用生成器的代码，按 game.js 的规则从头模拟：
  python3 verify/verify_levels.py 导出的关卡.json --wordbank /path/to/wordbank --report report.json
wordbank 目录要有 question_words_v2.csv、validation_words.txt、allowed_mild_words.txt、flagged_offensive.txt、specialist_words.csv。
有问题的关会逐条列出，全部通过时退出码为 0。verify/negative_samples.json 是故意做坏的关（次数少一、漏额外词、加连不出的词、有死局），用来确认脚本能抓到。

sample_320_levels.json 是测试时生成并导出的 320 关（种子 test-320），verify/report_320.json 是它的校验报告。
