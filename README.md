# 字页关卡台

单文件关卡编辑器，双击 `wordpages-level-desk.html` 在浏览器打开，无需安装。

在线地址（启用 GitHub Pages 后）：https://sgggom.github.io/word-editor/

启用方式：仓库 Settings > Pages，Branch 选 **main**、文件夹选 **/ (root)**。根目录的 `index.html` 与 `wordpages-level-desk.html` 内容相同，打开上述地址即进入编辑器。空文件 `.nojekyll` 用来关闭 Jekyll 处理。

## 目录

- `wordpages-level-desk.html` — 编辑器本体（单文件，本地双击即可用）
- `index.html` — 与上面完全相同的副本，供 GitHub Pages 根地址使用
- `sample_320_levels.json` — 测试时生成并导出的 320 关
- `src/` — 生成器与界面脚本（`gen.js`、`batch_ui.js`）、词库与策略、无头测试和截图
- `verify/` — 独立 Python 校验脚本、负样本和 320 关校验报告
- `shots/` — 多宽度布局截图与布局测试
- `dict/` — 释义，按首字母分成 `a.json` … `z.json`，悬停时按需加载。dictionary uses ECDICT (MIT), Open English WordNet (CC BY 4.0), CMUdict (BSD), and some English definitions adapted from Wiktionary (CC BY-SA 4.0).
- 校验词库是 13,485 个词：Word Tiles 和 Zen Word 全部关卡用词、分级题库（8,604）和 familiar_words_v1 的并集，去掉脏话和专名，温和词仍保留。罕见度嵌在编辑器里，按五档各一串词（0 简单、1 常见、2 稀有、3 罕见、4 极其罕见），覆盖这 13,485 个词。简单和常见不标标签；稀有、罕见、极其罕见才标，悬停卡片上也只对后三档标出。常见度分数 0–1（越高越常见）和仍有数据的 Zipf 并排显示。必答从这里面的第 0、1 档取（3–7 字母，排除专业词、温和词、标记词和屏蔽词）；额外词是这块盘上能连出的其余所有词库词。Prevalence scores are from Brysbaert et al. 2019, for internal use; the license is to be confirmed before shipping.

鼠标停在编辑器里出现的单词上（必答词、额外词、检查与提示里的词、建议词、Zen 参考、试玩里已经露出的词、正在连出的词等），大约 0.15 秒后弹出小卡片：单词、音标、中文释义、英文释义。稀有、罕见、极其罕见的词还会带上等级。词库不写进 HTML。第一次指到某个首字母才请求对应的 `dict/*.json`，之后用缓存。浏览器直接打开本地文件（`file://`）读不到这些文件时，卡片写「释义需要在线打开（GitHub Pages）或用本地服务器打开」；词库里没有的词写「暂无释义」。试玩里把词表藏起来时，还没找到的词是空槽，指上去没有释义；找到并露出之后才有。

顶上「词库」打开全部 13,485 个词。可以按罕见度、词长、首字母、用途（可做必答 / 仅额外 / 温和词 / 排除）和是否已在当前关序里用过这些条件一起筛，每组旁边是数量。排序可以按常见度、Zipf 或字母。列表分页，一行是单词、第 2–4 档的等级、常见度 · Zipf 数字，以及从 `dict/` 按需取来的简短中文释义；指上去仍是原来的释义卡片。筛完的结果可以导出 CSV 或 TXT。

同一个查找框在顶栏和词库里各有一个。精确查找会打开一张卡片：在不在这 13,485 个词里（不在就写「不在词库里」；若能从屏蔽词、标记词、温和词、专业词名单上认出原因就一并写出来）、档位、常见度、Zipf、能不能做必答、音标和中英释义，以及当前关序里哪些关把它当作必答或额外，点一下就跳到那一关。以前在大词表里、现在被拿掉的词也是这句「不在词库里」。查找方式还可以换成前缀、包含，或通配（`?` 是一个字母，`*` 是任意长度，例如 `C?T`）。

打开页面时不再放入示例关。上次编辑过的关序自动存在这个浏览器的 IndexedDB 里，超过 40 关也会存；下次打开接着用。什么都没存过，就从一关空棋盘开始。示例还在，要点「加载示例」，或在地址后加 `?sample=1`。`?fresh=1` 这次不读存档，从空关开始，不会把已经存下的关序擦掉。

「打开」在 Chrome / Edge 里用系统文件框（File System Access），选中的文件记在「打开历史」里：文件名、上次打开时间、关数，以及文件句柄。再点某一条会重新打开（需要的话先要读取权限）。打开这份列表时会核对每条还在不在磁盘上；对不上的变灰，写着「文件已不存在」，关掉列表后从历史里删掉。「保存」写回当前打开的那个文件；「另存为」另选一个。Firefox / Safari 没有这套文件接口，历史里只留文件名和一份内容，标成「浏览器缓存副本」，不能核对磁盘上的文件还在不在，可以手动删除。粘贴导入不记历史；从文件导入或保存才会记。

试玩这一关时，左边同时列出必答词和额外词。额外词单独一块，标题是「额外词 x / N」，连出来的会标成已找到。旁边的按钮在「显示词表 / 隐藏词表」之间切换，选择记在这个浏览器里。显示时每个词都看得到，找到的会标出来。隐藏时，还没找到的词只画出和字母数一样多的空槽，找到后才在原来的位置露出全文；必答和额外都这样。额外词很多时，列表在自己那一块里滚动，不会把整页撑开。可以用「上一关 / 下一关」，或键盘 ← →、PageUp、PageDown（焦点在输入框里时不会抢走按键）。旁边显示「第 M / N 关」。换关会重新打开那一关，并在关序里选中、滚到可见处。不能导出或试玩的关会跳过，并短暂说明原因；到头时对应按钮禁用。过关后，完成提示下面也有「下一关」。

字页关卡台 v4
=============

v4 修复：关很多（几百上千关）时页面不再无限变宽。关序柱子只在自己那一栏里左右滚动，
整页不会横向滚动，顶部按钮不动。超过 150 关柱子变窄，超过 400 关更窄并隐藏关号；
选中的关会自动滚到可见处；关序栏左上角可以输入关号直接跳转。柱子下面的重复提示只占一行，
放不下用省略号，鼠标悬停看全文。生成器逻辑没有改。

（以下为 v3 说明）

打开 wordpages-level-desk.html（双击或用浏览器打开）。不需要安装，不改游戏仓库。
v2 的功能都在：手动排关、四个难度维度、试玩、导入 Word Tiles / Zen、导出游戏关卡。

新增：顶上「批量生成」
--------------------
设置：起始关号、关数、插在当前关后面或替换整条关序、起点/终点难度、爬升用多少关、
每几关一个峰值、峰后回落幅度、一格最多用几次、允许的棋盘尺寸、随机种子（同样设置 + 同样种子 = 同样的关）。
下面的小曲线是难度预览：缓慢爬升，每段末尾一个峰值，峰后马上回落（Word Tiles 的节奏）。

怎么出一关（先构造）
  1. 按难度定四个维度：必答数、棋盘尺寸、最长词长度、词汇门槛（常见度分数：简单关只用 0.85 以上的简单词，难关放到 0.72，也就是简单和常见；难度高时最多 1 个稀有词，标为“生僻”。罕见和极其罕见不做必答）。
  2. 先放一个最长的词，再用 3–4 字母的熟词一条条铺，每条都是真正上下左右相连、不重复用格的路径，直到每一格都有字母。
  3. 再从这块盘上连得出的熟词里补到目标必答数（约八成是 3–4 字母）。
  4. 每格的使用次数 n = 这些路径经过它的次数。所以一开始就有一套完整解，最后一个词也是连好的。
  5. 额外词 = 盘上能连出的其余所有校验词（3–10 字母）。

怎么查（再穷举）
  每一关都把“所有找词顺序 × 每个词所有可走路径”完整走一遍：
  - 从开局必须能走完；
  - 任何一种走法都不能走进死局（某个时候剩下的词怎么都连不出来）。有一个死局这一关就丢掉重出；
  - 游戏自己的 solve()（6 万步预算）也必须在开局算得出解。
  丢掉的草稿按原因计数，生成完显示在面板里。条件太紧时会自动把这一关降一点难度再试，也会写出来。

必答词的规则：从全部校验词里取常见度第 0、1 档（简单、常见），长度 3–7 个字母；不用专业词、温和词（ass/sex 等那 23 个，只能当额外）、
flagged_offensive 里的词、屏蔽词；前后 10 关内不重复。更难的关可以再放最多一个第 2 档（稀有）。第 3、4 档只出现在额外词里。

生成后
  生成的关会进到上面的关序里，可以照常点开手改。没改过的关，导出时用构造出来的使用次数；
  改了字母或必答，就按当前盘面重算，检查栏会提示。每一关的检查栏都多了一行“穷举试玩”的结果（手排的关也有）。
  关序自动存在这个浏览器里（IndexedDB），超过 40 关也会存。「保存」写的是关卡台自己的文件，里面留着关名、分册和编辑状态。

  「导出游戏关卡」是给游戏的主文件，缩进 2：`{ "books": [ { "name", "sub", "mix", "levels" } ], "daily": [ ... ] }`。每一关固定 9 个键，顺序是 id、name、g、t、n、e、lv、ty、curtains。id 是数字的字符串，分册从 `"1"` 连着编，daily 接在分册后面。name、ty 没有就写 `""`。幕布是 `curtains: [{ "req", "cells" }]`，没有幕布就是 `[]`，不再写 o。mix 跟导入时一样保留；新分出来的册按 lv 里 1–5 的比例算成五个整数，加起来是 100。

  默认全部关都在第一册（副题「入门」），`daily` 是空数组。新关、生成的关、以及导入时没有分册信息的关卡数组都这样。只有导入文件里已经写了 books / daily，或在导出框里自己把关分到别的册、放进 daily，才会拆开。导入这份文件再原样导出，关卡内容和分册都保持一致。编辑器新做的关，lv 仍按必答词顺序写成罕见度：简单 1、常见 2、稀有 3、罕见 4、极其罕见 5。

  「导出为 levels.js（分册）」是次要格式：一行注释，然后 `window.BOOKS=[...]`，有每日关时再加 `window.DAILY`。id 在这里是数字，幕布写成 o。导入也认 `window.BOOKS` / `window.DAILY`、单个关卡和关卡数组。

独立校验脚本
------------
verify/verify_levels.py 是另写的 Python 脚本，不用生成器的代码，按 game.js 的规则从头模拟：
  python3 verify/verify_levels.py 导出的关卡.json --report report.json
词表用仓库里的 `src/lex.json`（五档罕见度）和 `src/policy.json`（屏蔽、标记、温和、专业词）。必答须是第 0 或 1 档，一关最多一个第 2 档。编辑器新做的关把这五档写成 lv 里的 1–5；从游戏文件导入的 lv 原样保留。
有问题的关会逐条列出，全部通过时退出码为 0。verify/negative_samples.json 是故意做坏的关（次数少一、漏额外词、加连不出的词、有死局），用来确认脚本能抓到。

sample_320_levels.json 是测试时生成并导出的 320 关（种子 test-320），verify/report_320.json 是它的校验报告。
