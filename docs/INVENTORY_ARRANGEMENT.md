# 关卡库与排布（2026.10.22.1）

## 数据流和边界

生产只写命名关卡库，排布只读库存并保存草稿、预览。只有完整预览复核通过并确认应用，才创建正式关序。默认 100 关、历史存档及词库表不自动迁入库存，也不自动绑定新规则。

- `WTEngine.generatePoolAttempts(spec, index, profiles, config, start, count)` 接收固定尺寸与目标词数，返回按候选编号排列的成功结果或 `null`。不使用逐关字母表、关号阶段或用词历史。
- 参考模板按 list0 的目标数差、格数差、原模板顺序排序。铺盘、扫描和选词仍沿用原引擎；不按最终总评分淘汰合法候选。
- `WPBatchGenerator.generateCandidates` 保持返回顺序，线程失败时重新执行相同范围。每候选独立种子，单线程与多线程结果相同。
- 每次最多生产 10000 关；预算默认目标数 × 300。以 32 次尝试为一组提交，中止保留已提交结果。失败、重复不抵扣目标量，均消耗尝试预算。
- 同规格、来源、种子在同一库继续生产时按已保存游标追加。游标保存失败最多导致重扫重复候选，不会覆盖或删除原库存。

## 库文件及存储

`wordpages-level-pool` schema 1 保存 `pool: {id, name}`、`entries` 与 `librarySnapshots`。每条记录包含：

- `id` 与完整 `signature`，校验哈希冲突；展示编号和名称不影响身份。
- `playKey`：棋盘加排序后的必答词。排布据此阻止不同库中同一关重复使用。
- `game`：九字段棋盘、逐格次数、目标与额外词。
- `librarySnapshotId`：共享不可变词库快照引用。
- `generation`：批次、种子、候选序号、尺寸、目标数、单格次数上限、引擎版本。
- `metrics`：尺寸、目标数、字母集合、每词最少拐弯路径、直线／一拐／多拐词数及最大拐弯。

独立 IndexedDB `wp.leveldesk.pools` 包含 `pools`、`entries`、`snapshots`、`workspace` 四个 store。库存键为 `[poolId, id]`，`poolId` 索引支持 50 条分页。库存、数量和快照在同一写事务内提交。导入先完整校验文件，重算指标，然后每 100 条写入；空间不足时保留已成功的批次，原库存不受损。

导入同名文件可以新建库或合并到指定库。首次导入保留源库 ID，便于排布方案找到来源；本机已有相同 ID 又选择新建时另建 ID。合并去重不修改原记录。跨多个库的同一关在排布中只占一个候选。

库存仅接收支持尺寸、2–16 个目标词、无帘子的完整有效关卡。帘子不是当前生产器输出；旧关序中的帘子仍由原编辑器处理。导入会验证快照、目标权限、额外词完整性、所有目标可达、路径用格一致、覆盖和逐格次数，不仅检查元数据。

## 排布文件与规则

`wordpages-arrangement` schema 1 保存名称、种子、预算、连续分段、尺寸／词数逐关覆盖和逐关字母表快照。分段必须从 1 开始连续覆盖，排布位置最多 10000 个；每段引用一个或多个库 ID。

每个位置先精确匹配来源、尺寸、词数、必含字母和拐弯限制。必含字母检查整盘，表外关号无字母限制。拐弯取每个必答词所有合法路径中的最小值；生成器本身还要求所有可接受路径使用相同格子，以保证逐格次数和解答顺序安全。

重复词仅统计必答，gap=20 时位置差须至少 21；gap=0 关闭。密度窗口包含当前关，每个字母每关最多记一次，前面不足完整窗口时上限不缩放。历史跨段延续，由当前段规则判断。缺位消耗位置但不贡献内容；按正式编号算间隔和窗口。

严格规则排除候选。软规则每个违反的必答词或字母条件计 1 分，各项等权；数量超出多少不额外加权。静态候选稀缺性优先保护只能供后续使用的库存，余下顺序由种子稳定决定。候选排列不受数据库读取顺序影响。

搜索在 Worker 中进行；没有 Worker 时分段执行并让出主线程。默认 100 万次候选检查。每个位置保留至多 8 个备选，回退窗口至多 20 个前置位置，优先保留匹配数最多、软违规最少的结果。有限搜索不保证找出存在的所有解，也不宣称缺口无解。

缺口原因包括：

| 标识 | 含义 |
|---|---|
| `static` | 没有满足静态条件的库存 |
| `temporal` | 本次搜索可用库存被严格间隔／密度限制排除 |
| `unmatched` | 符合条件的库存已使用，本次搜索未匹配 |
| `budget` | 检查预算耗尽，尚未匹配 |
| `cancelled` | 用户中止，尚未匹配 |

预览保留全部正式编号、各位置静态要求、候选数和选中来源；统计包含全局拐弯数量、必答词重复次数与间隔、软违规以及每个已匹配位置的字母窗口计数。页面按 50 关展示统计和结果，便于定位缺口。

## 应用、编辑与兼容

应用前重新读取完整记录与快照、校验内容并复核所有规则，防止采用过期预览。正式关号为 1…N，来源池 ID 和候选 ID 保留在每关 `arrangement` 元数据。规则快照在正式关序 `arrangement.plan` 保存。应用复制记录，不修改库存；撤销可恢复原关序。

手动修改后的指标由实际棋盘重算；游戏导出前复核新关序绑定规则。原有未绑定规则的默认关卡、旧存档按原校验流程处理。关卡台文件仍为 schema 2，增加可选 `arrangement`；游戏文件九字段不变。

## 验证与复现

纯引擎验证：

```sh
node tests/pool_arrangement.cjs
POOL_SCALE=1 node tests/pool_arrangement.cjs
node tests/inventory_scale.cjs
```

浏览器测试先启动 HTTP 服务，另提供 `puppeteer-core` 和 Chromium：

```sh
python3 -m http.server 8000 --bind 127.0.0.1
NODE_PATH=/path/to/node_modules CHROMIUM_PATH=/path/to/chrome node tests/browser_inventory_arrangement.cjs
NODE_PATH=/path/to/node_modules CHROMIUM_PATH=/path/to/chrome node tests/browser_inventory_scale.cjs
```

`BASE_URL` 可替换服务地址，万关库默认放在系统临时目录 `wordpages-inventory-10000.json`。所有验收库存均是测试数据，不写入发布 HTML 或仓库。

本机 Chrome 实测：10000 个真实合法关卡共 31892 次尝试，Node 生产及逐关验证约 19.4 秒；文件约 12.4 MB。浏览器分批导入约 7.7 秒，共享一份词库快照。使用原 1000 关字母表、默认最多一拐和严格间隔 20，100 万次候选检查约 52.9 秒，匹配 956/1000，正确保留 44 个缺口并禁止应用。主线程 50 ms 心跳最大间隙约 391 ms，期间可操作和取消。实际匹配数反映这批库存和搜索预算，不保证任意库存能排满。

另用独立的可匹配摘要夹具验证 10000 库存／1000 位置完整匹配、无重复占用。为隔离库存条件不足与编辑器容量，再使用同一批真实库存、无逐关字母限制的测试表、关闭间隔与拐弯限制，完整排布 1000 关约 3.4 秒，应用约 0.4 秒；千关规则复核、九字段导出、共享快照、保存和刷新恢复均通过，期间主线程心跳最大间隙约 126 ms。该测试表仅用于验收，正常界面仍使用原 1–1000 关字母表。真实完整记录的生成校验、导入导出、分页、快照共享、1000 位预览、刷新恢复由浏览器规模用例覆盖。两份离线 HTML 的生产 Worker、导入、排布、应用和规则复核均单独验证。
