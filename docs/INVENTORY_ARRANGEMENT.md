# 关卡库与排布（2026.10.26.1）

## 数据流和边界

生产只写命名关卡库，排布只读库存并保存草稿、预览。只有完整预览复核通过并确认应用，才创建正式关序。默认 100 关、历史存档及词库表不自动迁入库存，也不自动绑定新规则。

2026.10.23.2 起，生成面板同样占满固定视窗：来源词库、生产批次、库存各自滚动，底部保留运行操作与进度。顶部统一选择写入／浏览的关卡库，“库操作”提供重命名、导入合并和导出；种子历史与高级参数放在运行设置对话框，修改即时保存。屏宽不足时来源和批次上下排列，手机通过页签分别查看三个区域。

生成时锁定影响结果的配置，仍可翻库存页、切换移动端视图、查看只读运行设置和中止。已提交的候选以约 700 ms 的节奏分批刷新到当前库存分页，读取序号防止旧分页响应覆盖新页。关闭工作台后运行继续，再次打开可看当前进度；测试使用独立浏览器上下文，不改用户当前关序或本地库存。`tests/browser_generation_layout.cjs` 覆盖固定视窗、多个批次、分页试玩、参数和种子历史、运行锁定、中止保留库存及两份离线 HTML。

2026.10.22.5 起，排布界面使用固定视窗的三栏工作台，规则与列表各自滚动，底部操作始终可见。只渲染当前分段的表单；逐关条件和结果合并，每页最多 50 个位置。分段卡片、范围筛选、缺口筛选与统计跳转只影响查看范围，排布仍处理完整方案。单关改动有标记，可恢复继承或重置当前段全部例外。复制分段将规则追加到关序末尾，不搬移原有正式关号或复制原关号的单独设置；删除分段后不自动压缩关号，范围不连续时提示修正。

来源库与字母密度使用独立编辑窗口，密度的取消／Esc 不修改方案。种子与预算设置延续自动保存和历史复用。统计展示整套关序的结果；逐关密度随关序表的筛选、分页同步。规则修改后显示旧预览标记并禁止应用；单纯切换分段或视图不会让预览失效。无效的单关输入保留在表内供修正，不会丢失整张表。

- `WTEngine.generatePoolAttempts(spec, index, profiles, config, start, count)` 接收固定尺寸与起始首字母，返回按候选编号排列的成功结果或 `null`。新生产规格使用 `strategy: "straight-initials-v1"`、`initialLetters`，不预设目标词数，不使用逐关字母表、关号阶段或用词历史。
- 新生产不再需要 list0 模板：先直线铺短词，再扫描决定必答列表。不按总评分淘汰合法候选。仅保留显式旧 `targetCount` 规格的纯引擎接口用于旧脚本复现；界面统一使用新算法。
- `WPBatchGenerator.generateCandidates` 保持返回顺序，线程失败时重新执行相同范围。每候选独立种子，单线程与多线程结果相同。
- 每次最多生产 10000 关；预算默认目标数 × 300。以 32 次尝试为一组提交，中止保留已提交结果。失败、重复不抵扣目标量，均消耗尝试预算。
- 同规格、来源、种子在同一库继续生产时按已保存游标追加。游标保存失败最多导致重扫重复候选，不会覆盖或删除原库存。

## 目标词长度（2026.10.26.1）

`src/lengths.js` 提供共享长度统计、铺盘偏好校验和正式关号规则。统计只使用实际必答词；旧库存读取、摘要、导入和导出时重算，不修改关卡 ID、签名或词库快照。

- 开局档：3×3，必答长度仅 3；原来词库中可达的其他长度词可作额外词。
- 常规小棋盘：3／4 或 3／4／5，包含 3、4，5 可选。没有 5 字母词时，4 字母词计作本关长词；有 5 字母词时，3／4／5 对应短／中／长。
- 常规大棋盘：至少一个恰好 5 字母必答词，可保留其他合法 3–8 字母词；6 字母词不能代替这项要求。
- 原算法档：保留 `straight-initials-v1` 候选流。长度生成使用独立 `length-guided-v1` 随机流，档位和有效比例纳入续生成游标。

每种尺寸可保存 3／4／5+ 字母的整数权重，合计 100%；默认分别为 4×2：65／30／5，3×3：65／25／10，4×3：50／35／15，5×3：45／35／20。权重指导铺盘，不是最终词数比例的硬限制。常规档先直线放入指定首字母短词，再尝试必要词长，按偏好补盘，后续放词可使用最多一拐路径。最终扫描中意外形成的多拐词仍由排布规则筛选。长度范围内的合法词全部保留，5 字母偏好为 0 也不会删除已扫描出的合法 5 字母词。

排布方案使用 `targetLengths: true` 和 `targetLengthVersion` 绑定规则，前 2 个正式位置应用开局规则，其余位置按尺寸应用常规规则。长度判定属于静态条件，优先于重复词／密度处理和情绪分排序。比例只用于生产，不改变已确认的情绪分第三优先级。旧方案缺少开关时保持关闭；新方案默认开启并设置前两关 3×3。正式关序保存绑定方案，手改后导出前再次复核长度；旧默认关序不会自动套用。

`lengthCounts` 保存逐长度实际词数，`shortCount / mediumCount / longCount / longMinLength` 保存本关分类，其中无 5 字母时 4 字母只计长词，不重复计作中词。原始逐长度分布始终可查看。新预览保存词长规则版本和全套长度统计，旧版本预览不可按新词长规则直接应用。

验证：`node tests/word_lengths.cjs`、`node tests/browser_word_lengths.cjs`，包括两种小棋盘组合、5 字母非强求与大棋盘精确 5 字母条件、开局档、旧库存指标、比例保存、线程、正式前两关、旧方案兼容和两份离线 HTML。

## 每批首字母与直线生产

2026.10.23.1 起，每个批次填写棋盘尺寸、起始首字母、生成数量。首字母可写 `ABC` 或 `A B C`，支持小写、空格、逗号等分隔，去重排序后用于生成；留空不限。旧生产草稿保留尺寸和数量，原目标词数不再生效，首字母初始为空。当前关序、库存和历史方案不会重写。

1. 只从所选生效必答候选中取 3／4 字母词。先按配置的首字母分组，随机打乱各组及组内词，轮流尝试放置。
2. 穷尽合法横／竖直线路径，随机选一个位置及方向。允许同字母交叉，禁止覆盖冲突字母；每次至少新增一格，同一铺盘词不重复。一个词放不下时继续尝试其余词；所有指定首字母都无可继续放置的词，才结束这一阶段。
3. 用其他 3／4 字母必答候选按同样的直线规则继续填充，最后空格按字母频率随机补齐。3×3 只接受 3 字母直线，其他尺寸依实际行列长度允许 4 字母词。首字母影响起始铺盘，不强制每个配置字母出现，也不约束所有最终必答词的首字母；没有可用短词会阻止开始，部分字母没有可用词会提示。
4. 扫描完成的棋盘，保留全部 3–8 字母、可达且路径用格一致的必答候选；无需固定词数，也没有 16 词上限。放入的短词都须留在必答中，所有格子须有必答覆盖，逐格计数不得超过所设上限。失败即舍弃整次候选，不截断词表来凑数。不可安全用作必答的可达词仍按原规则列为额外。
5. 最后自动扫描全量额外参考词，保存指标和完整关卡。直线铺盘仍可能连出拐弯词，最终由排布的拐弯条件筛选。

算法版本、规范化首字母加入候选随机流及续生成游标；相同输入、种子、候选范围不受线程数影响。`generation` 保存实际词数、首字母以及每次放置的单词、格子、阶段和新增格数，可随关卡库文件往返。排布仍按最终实际词数精确匹配。

大词数关卡的试玩先检查每词所有路径是否消耗相同格子、逐格计数是否等于这些需求之和。满足时，移除任意已答词后，剩余计数恰好等于剩余词的需求，因而任意答题顺序都安全；无需枚举指数级顺序。其余情况继续有界穷举，单词完成状态改用 BigInt，避免 32 位溢出。

`tests/straight_generation.cjs` 验证直线穷尽、交叉和首字母、全部合法词保留、额外词独立性、超过 16／31 词的导入、排布与校验。`tests/browser_straight_generation.cjs` 验证多批次、旧草稿升级、续生成、线程一致性、大词数试玩及在线／两份离线页面。

## 额外词只用于校对

2026.10.22.4 起，生成面板只选择必答来源。`WPLibrary.production` 自动附上全量额外词校对参考：四款游戏额外词并集，排除已有必答候选与两字母词，共 11,692 词，与当前精简版原始表的额外词页一致。词库窗口的额外词配置仍可浏览、编辑，但不影响这份自动参考；旧的额外来源选择不再用于生产。

铺盘、选词与必答路径验证使用独立的必答索引。棋盘通过校验后扫描完整词表，写入可达且未选为本关必答的额外词，包括未选中的必答候选。额外词数量只作结果统计，不参与评分或淘汰。候选游标按生效必答词内容、种子和规格识别，校对参考变化不会重新开始候选编号。旧库存和正式关序仍使用其绑定快照，不自动重算额外词。

`tests/generation_extras.cjs` 对比有／无全量额外词的相同候选范围，验证成功率、棋盘、必答词、路径、逐格次数和评分一致，同时确认额外词正常增加及快照往返一致。

## 情绪评分与选取优先级

2026.10.22.6 起，`src/emotion.js` 读取内嵌精简版词表，按关卡的实际必答和额外列表计算 `emotionScore = targetSum + extraSum × 0.5`。负分和半分保留；重复词只计一次，已在必答列表中的词不重复计为额外。未收录或无数值的词按 0 分计，明细保留缺失名单；表内数值 0 是有效的中性标注。

`metrics.emotion` 保存分项、缺失名单和评分版本，`metrics.emotionScore` 用于排序。评分版本由公式版本和全部有效单词情绪数值决定，不依赖释义等显示字段。生成、导入和文件导出使用当前评分；IndexedDB 的列表、详情和摘要读取时重算，因此已有库存无需重新生成，不修改候选签名或 ID。仅修改额外词也会触发正式关序统计重算。

排布先排除硬性不合格候选，保护后续关号唯一的库存，再按软规则扣分升序、情绪分降序、稀缺性和种子次序选择。在有界回退中，匹配关数优先；同等匹配数先取软扣分少的结果，再取总情绪分高的结果。搜索保留预算、取消、缺口诊断；不保证全局最优。软规则不能被高情绪分抵消，扫描不再因前 256 个高分候选都有扣分而提前忽略后面的低扣分候选。

排布方案 `ranking` 记录规则版本、词表评分版本和额外权重 0.5，预览同时记录评分版本与逐关分数。评分版本更新后，旧预览可查看但不能直接应用，需要重新排布。旧正式关序、旧游戏文件不自动重排，游戏九字段格式不变。

`tests/emotion.cjs` 验证公式、优先级、缺失标注、负分、稀缺性、多库重复和预算；`EMOTION_SCALE=1 node tests/emotion.cjs` 检查万关库存、千个排布位置。`tests/browser_emotion.cjs` 覆盖旧数据库指标刷新、界面、线程一致性、存档、手改额外词及两份离线 HTML。

## 随机种子与历史

2026.10.22.3 起，生成和排布默认“每次随机”，在配置校验通过、实际开始运行时换新种子。参数校验失败不创建使用记录。运行期间固定该次种子，线程回退、分批写入和取消不会偷偷换种子。生成记录的 `generation.seed` 与排布预览、方案中的 `seed` 均为实际使用值。

两套工具各自的“种子历史”保存完整使用记录，不自动裁剪。记录包含时间、种子、目标库／方案、请求关数和最终结果；中止、预算耗尽和失败同样留档。尚无最终结果的记录保留“已开始”状态，不虚构完成数量。历史按记录 ID 在 IndexedDB 事务中合并，多窗口使用时不会整表覆盖其他窗口的记录；重新打开工具会读取最新历史。升级前保存的种子标为“旧配置”留在历史，默认模式仍切为每次随机。

选择历史记录会进入“复用当前种子”，可直接重用或手动编辑；方式设置也会保存。历史回选只替换种子，不回滚参数、词库或库存。同一生成库和规格沿用原游标继续追加，新库可用相同参数和种子从头生成；排布结果还取决于当时库存和完整规则。导入带种子的排布方案使用文件中的种子；“下次用新种子”可恢复自动随机。

记录保存在 `wp.leveldesk.pools` 的 `workspace/seedHistory`，模式保存在 `workspace/seedModes`，与当前正式关序分开。当前浏览器、HTTP 站点与本地文件各自的存储范围仍遵循浏览器隔离规则。

## 库文件及存储

`wordpages-level-pool` schema 1 保存 `pool: {id, name}`、`entries` 与 `librarySnapshots`。每条记录包含：

- `id` 与完整 `signature`，校验哈希冲突；展示编号和名称不影响身份。
- `playKey`：棋盘加排序后的必答词。排布据此阻止不同库中同一关重复使用。
- `game`：九字段棋盘、逐格次数、目标与额外词。
- `librarySnapshotId`：共享不可变词库快照引用。
- `generation`：批次、种子、候选序号、尺寸、实际目标数、首字母、放置记录、单格次数上限、引擎版本。
- `metrics`：尺寸、目标数、字母集合、每词最少拐弯路径、直线／一拐／多拐词数及最大拐弯。

独立 IndexedDB `wp.leveldesk.pools` 包含 `pools`、`entries`、`snapshots`、`workspace` 四个 store。库存键为 `[poolId, id]`，`poolId` 索引支持 50 条分页。库存、数量和快照在同一写事务内提交。导入先完整校验文件，重算指标，然后每 100 条写入；空间不足时保留已成功的批次，原库存不受损。

导入同名文件可以新建库或合并到指定库。首次导入保留源库 ID，便于排布方案找到来源；本机已有相同 ID 又选择新建时另建 ID。合并去重不修改原记录。跨多个库的同一关在排布中只占一个候选。

库存仅接收支持尺寸、至少一个必答词、无帘子的完整有效关卡，不再限制为 2–16 词。帘子不是当前生产器输出；旧关序中的帘子仍由原编辑器处理。导入会验证快照、目标权限、额外词完整性、所有目标可达、路径用格一致、覆盖和逐格次数，不仅检查元数据。

## 排布文件与规则

`wordpages-arrangement` schema 1 保存名称、种子、预算、连续分段、尺寸／词数逐关覆盖和逐关字母表快照。分段必须从 1 开始连续覆盖，排布位置最多 10000 个；每段引用一个或多个库 ID。

每个位置先精确匹配来源、尺寸、词数、必含字母和拐弯限制。必含字母检查整盘，表外关号无字母限制。拐弯取每个必答词所有合法路径中的最小值；生成器本身还要求所有可接受路径使用相同格子，以保证逐格次数和解答顺序安全。

重复词仅统计必答，gap=20 时位置差须至少 21；gap=0 关闭。密度窗口包含当前关，每个字母每关最多记一次，前面不足完整窗口时上限不缩放。历史跨段延续，由当前段规则判断。缺位消耗位置但不贡献内容；按正式编号算间隔和窗口。

严格规则排除候选。软规则每个违反的必答词或字母条件计 1 分，各项等权；数量超出多少不额外加权。静态候选稀缺性优先保护只能供后续使用的库存，余下顺序由种子稳定决定。候选排列不受数据库读取顺序影响。

搜索在 Worker 中进行；没有 Worker 时分段执行并让出主线程。默认 100 万次候选检查。每个位置保留至多 8 个备选，回退窗口至多 20 个前置位置，优先保留匹配数最多、软违规最少的结果。有限搜索不保证找出存在的所有解，也不宣称缺口无解。

缺口原因包括：

| 标识 | 含义 |
|---|---|
| `static` | 没有满足静态条件的库存 |
| `temporal` | 本次搜索可用库存被严格间隔／密度限制排除 |
| `unmatched` | 符合条件的库存已使用，本次搜索未匹配 |
| `budget` | 检查预算耗尽，尚未匹配 |
| `cancelled` | 用户中止，尚未匹配 |

预览保留全部正式编号、各位置静态要求、候选数和选中来源；统计包含全局拐弯数量、必答词重复次数与间隔、软违规以及每个已匹配位置的字母窗口计数。页面按 50 关展示统计和结果，便于定位缺口。

## 应用、编辑与兼容

应用前重新读取完整记录与快照、校验内容并复核所有规则，防止采用过期预览。正式关号为 1…N，来源池 ID 和候选 ID 保留在每关 `arrangement` 元数据。规则快照在正式关序 `arrangement.plan` 保存。应用复制记录，不修改库存；撤销可恢复原关序。

手动修改后的指标由实际棋盘重算；游戏导出前复核新关序绑定规则。原有未绑定规则的默认关卡、旧存档按原校验流程处理。关卡台文件仍为 schema 2，增加可选 `arrangement`；游戏文件九字段不变。

`BASE_URL` 可替换服务地址，万关库默认放在系统临时目录 `wordpages-inventory-10000.json`。所有验收库存均是测试数据，不写入发布 HTML 或仓库。

2026.10.23.1 新算法验收使用核心必答词库、全量额外校对、各尺寸首字母 `ABC`：21,915 次尝试得到 10,000 个不重复有效候选，实际词数 2–26，Node 生产和逐关验证约 4.4 秒，文件约 19 MB。Chrome 分批导入约 30.8 秒；保留原逐关字母表、固定 3×3／3 词、最多一拐和严格间隔 20 的 1000 个位置，在 100 万次检查预算内匹配 208 个，其余保留缺口，约 78.3 秒；50 ms 心跳最大间隙约 547 ms。该结果反映这批起始首字母与实际词数分布不适合整套原关序，不能视为无解。

另按库存的实际尺寸和词数设置 1000 个位置，使用中性字母测试表、关闭拐弯和间隔限制，完整匹配约 3.1 秒、应用约 0.5 秒；共享快照、规则复核、九字段导出、刷新恢复均通过，库存仍为 10,000 条。此阶段心跳最大间隙约 177 ms。在线及两份离线 HTML 另外验证了 26 词关卡的生成／导入、排布、保存、导出和试玩。测试文件只写入系统临时目录。

旧版固定词数生产器的 Chrome 实测：10000 个真实合法关卡共 31892 次尝试，Node 生产及逐关验证约 19.4 秒；文件约 12.4 MB。浏览器分批导入约 7.7 秒，共享一份词库快照。使用原 1000 关字母表、默认最多一拐和严格间隔 20，100 万次候选检查约 52.9 秒，匹配 956/1000，正确保留 44 个缺口并禁止应用。主线程 50 ms 心跳最大间隙约 391 ms，期间可操作和取消。实际匹配数反映这批库存和搜索预算，不保证任意库存能排满。

另用独立的可匹配摘要夹具验证 10000 库存／1000 位置完整匹配、无重复占用。为隔离库存条件不足与编辑器容量，再使用同一批真实库存、无逐关字母限制的测试表、关闭间隔与拐弯限制，完整排布 1000 关约 3.4 秒，应用约 0.4 秒；千关规则复核、九字段导出、共享快照、保存和刷新恢复均通过，期间主线程心跳最大间隙约 126 ms。该测试表仅用于验收，正常界面仍使用原 1–1000 关字母表。真实完整记录的生成校验、导入导出、分页、快照共享、1000 位预览、刷新恢复由浏览器规模用例覆盖。两份离线 HTML 的生产 Worker、导入、排布、应用和规则复核均单独验证。
