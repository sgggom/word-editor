# 批量生成的并行计算

2026.10.20.3 使用 Web Worker 并行搜索候选棋盘，页面负责进度、取消和接纳结果。设置可选自动或 1／2／4／8 线程；自动按浏览器报告的逻辑处理器数减一，取 1–4，手动上限是浏览器报告的处理器数与 8 的较小值。

## 关序与结果一致性

关卡需要前面关卡的累计用词次数和近期用词记录，因此按关序逐关生成。每关固定历史后，将其候选尝试拆成小组分给线程；每个候选由种子、主线、关号和尝试序号确定随机流。所有返回值按尝试序号归并，使用同一评分、择优、提前结束和失败规则。并发不增加每关尝试预算，不放宽覆盖、路径安全、词库权限或单格次数上限。

线程返回顺序和数量不改变结果。浏览器单线程、多线程、回退路径与 Node 都调用同一份引擎代码。由于本版将原来的连续随机流改成独立候选随机流，新生成的棋盘可能与旧版本相同种子的结果不同；已保存关卡的内容和快照不改写。新的编辑器关卡元数据包含 `gen.searchVersion: independent-attempts-v1`。

## 启停与失败

- 每批固定词库快照和配置，各线程只在启动时建立一次词库索引；同一关的历史也只在该线程第一次收到任务时传入。
- 同时在途的工作及待汇总结果有上限。提前选定结果后，迟到的候选不再写入关卡；线程可继续处理下一关。
- 中止立即终止线程、清理消息回调、计时器和 Blob URL。只接纳中止前已经完成的关卡；尚未完成任何关时保留原关序。
- 线程构造失败、消息错误、启动或计算超时会终止线程池，按同一历史和种子重试当前关，随后使用分段执行的单线程。界面显示实际计算方式。
- 生成期间打开另一条关序会中止旧任务；若原关序内容已经编辑，完成时不写入过期结果，并提示重新生成。单纯切换查看的关号不会触发这项保护。

生成设置在运行期间锁定，页面和中止按钮保持响应。线程源码以 JSON 字符串内嵌，启动时创建 Blob Worker；两份独立 HTML 均可通过 `file://` 运行，没有外部 worker 脚本依赖。实现参考 [MDN Web Workers](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers) 和 [hardwareConcurrency](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/hardwareConcurrency)。

## 性能实测

2026-10-20，本机 Chrome 155，浏览器报告 8 个逻辑处理器。list0 从第 51 关开始生成 40 关，每关最多尝试 120 次，种子 `parallel-benchmark`；两种词库均成功生成全部 40 关，所有线程数的棋盘、答案、额外词和次数一致。

1 线程、4 线程交替各运行三次，计入线程启动与索引建立时间，取耗时中位数：

| 词库 | 1 线程 | 4 线程 | 加速比 |
|---|---:|---:|---:|
| 核心必答 | 1,429 ms | 469 ms | 3.05× |
| 八库全选 | 2,578 ms | 828 ms | 3.11× |

原始样本和环境保存在 [worker_benchmark.json](../verify/worker_benchmark.json)。不同设备、词库、关卡阶段及批量大小的收益不同；少量关卡的线程启动成本占比更高，增加线程数也不会无限线性加速。
